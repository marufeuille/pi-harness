# チェックの中身と実行位置を見えるようにする

どのコマンドがチェックで、ワークフローのどこで走るのかを、`workflow.ts` を上から読んで分かるようにする。

## 現状

コマンドの一覧は設定の `checks` という文字列配列だけにある。実行は `reviewUntilAcceptable` の中で、検品の前に `runChecks` を呼んでいる。空配列のときは何も走らないことが、ワークフローの並びからは読めない。

## 入出力

- チェックは「名前」と「コマンド」を持つ。名前はワークフロー上の表示に使う。
- 実行位置は、実装の取り込みが終わったあと、賢いモデルの検品の前。
- コマンドが 0 件のときは、その段階を「チェックなし」としてワークフローのログに出す。
- 失敗したときの修正ループは、いまと同じ上限を使う。

## 受け入れ

- `workflow.ts` の実行順序を読んで、チェックの段階と、そこで使う定義の場所が分かる。
- 設定だけを開かなくても、どのチェックが登録されているかリポジトリ内で辿れる。
- チェックが空の実行でも、ログにその段階が出る。
