# プロファイラのログをセッション開始時に開く

ハーネスが Pi のセッションを始めるとき、プロファイラが `.pi-observability/*.jsonl` を作成し、ツール呼び出しを記録する。各段階のあと、そのファイルが `.harness/runs/<runId>/observability/<段階名>/` にコピーされている。

## 現状

`extensions/profiler.ts` は `session_start` でログファイルを開く。`src/harness/session.ts` はプロファイラを読み込むが、`session.bindExtensions()` を呼ばない。SDK の `createAgentSession` はそのままでは `session_start` を出さないので、ツールが動いてもログファイルは作られない。標準エラーの `[profiler] logging to ...` も出ない。

## 入出力

- セッションがプロンプトを処理し始める前に、ログファイルが開いている。
- 記録されるのは、そのセッションのツール呼び出し、所要時間、入出力の大きさ、同じ入力の繰り返し回数、エラーかどうか。
- セッションを破棄したあとも、その段階のコピーが run ディレクトリに残る。
- プロファイラ以外の拡張やスキルは、これまでどおり読み込まない。

## 受け入れ

- モデルを使うセッションを1回走らせると、標準エラーに `[profiler] logging to` が出る。
- そのパスに jsonl があり、セッション中のツール呼び出しが行として残る。
- ワークフロー完了後、`.harness/runs/<runId>/observability/` 以下の段階ディレクトリに、その jsonl がコピーされている。
- プロファイラが読み込めなかったセッションは、プロンプトを送る前に失敗する。
